# Panduan Utilities - 1.0.0

Panduan ini menjelaskan cara menggunakan utility publik yang disediakan library
pada aplikasi. Konfigurasi lengkap setiap feature flag tersedia di
[Panduan Konfigurasi](%281.0.0%29%20CONFIGURATION_GUIDE.md).

## A. Validation

### A.1. Konsep penggunaan

`ValidationUtility` adalah kontrak untuk menjalankan Jakarta Bean Validation
secara programmatic dari service. Umumnya validasi dipanggil melalui
`validateRequest()` pada alur `BaseService`:

```java
@Service
@RequiredArgsConstructor
public class CreateCustomerService
        extends BaseService<CreateCustomerRequest, CreateCustomerResponse> {

    private final ValidationUtility validationUtility;

    @Override
    protected void validateRequest(CreateCustomerRequest request) {
        validationUtility.validateRequest(request);
    }

    @Override
    protected CreateCustomerResponse buildProcess(CreateCustomerRequest request) {
        // Jalankan proses bisnis.
        return new CreateCustomerResponse();
    }

    @Override
    protected boolean useHttpServletParameter() {
        return false;
    }
}
```

Contoh service dan pemanggilan `execute()` dari controller tersedia pada
[Panduan Implementasi Service](%281.0.0%29%20SERVICE_IMPLEMENTATION_GUIDE.md).

### A.2. Konfigurasi wajib untuk validation handler

Jika aplikasi ingin memakai validation handler library, termasuk ketika bean
dibuat dengan `.useDefaultBehavior()`, aktifkan konfigurasi berikut:

```yaml
reyga:
  config:
    default-bean:
      validation-handler: true
```

Flag tersebut mempunyai dua fungsi:

- mengaktifkan `DefaultValidationExceptionHandler` agar
  `ValidationFaultException` diubah menjadi response HTTP validasi yang standar;
- menyediakan bean default `ValidationUtility` apabila aplikasi tidak membuat
  bean sendiri.

Bean `ValidationUtility` manual menentukan perilaku validasinya, tetapi tidak
menggantikan kewajiban mengaktifkan handler melalui YAML. Tanpa flag tersebut,
aplikasi harus menyediakan exception handler HTTP sendiri.

Flag `reyga.config.default-bean.exception-handler` boleh bernilai `false`.
Validation handler tetap aktif selama `validation-handler: true`:

```yaml
reyga:
  config:
    default-bean:
      exception-handler: false
      validation-handler: true
```

### A.3. Menggunakan default behavior

Untuk memakai seluruh konfigurasi default dari YAML, inject langsung
`ValidationUtility`; library membuat bean apabila belum ada bean milik aplikasi.

Jika aplikasi ingin mendefinisikan bean secara eksplisit, gunakan
`ValidationConfig`:

```java
@Configuration(proxyBeanMethods = false)
public class ApplicationValidationConfig {

    @Bean
    public ValidationUtility validationUtility() {
        return ValidationConfig.builder()
                .useDefaultBehavior()
                .build();
    }
}
```

`useDefaultBehavior()` memakai Jakarta Validator default, format detail berbasis
map, dan validation group Jakarta `Default`. Constraint yang gagal menghasilkan
`ValidationFaultException` dengan HTTP `400` dan response field error standar.

Atur bentuk diagnostic detail default melalui YAML:

```yaml
reyga:
  custom:
    validation:
      map-details: true
```

`map-details: true` menyertakan informasi per field untuk kebutuhan diagnostic.
Gunakan `false` apabila cukup menyimpan kumpulan pesan unik. Nilai ini digunakan
oleh bean default dari YAML; konfigurasi bean manual mengikuti pilihan builder.

### A.4. Pilihan `ValidationConfig.Builder`

| Method | Kegunaan |
|---|---|
| `useDefaultBehavior()` | Mengembalikan validator, detail, dan groups ke konfigurasi default. |
| `withValidator(validator)` | Memakai Jakarta `Validator` milik aplikasi dengan penanganan violation standar. |
| `withProcessor(processor)` | Memakai turunan `BaseValidationProcessor` milik aplikasi. |
| `useMapDetails()` | Memilih alur `violationsMapHandle()` dan detail diagnostic per field. |
| `useMessageDetails()` | Memilih alur `violationsSetHandle()` dan kumpulan pesan unik. |
| `withValidationGroups(Group.class, ...)` | Menetapkan groups default untuk pemanggilan tanpa groups eksplisit. |
| `build()` | Membuat `ValidationUtility` berdasarkan konfigurasi builder. |

`withValidator()` dan `withProcessor()` saling menggantikan. Jika
`useDefaultBehavior()` dipakai bersama konfigurasi lain, panggil method tersebut
lebih dahulu agar pilihan setelahnya tidak di-reset.

Contoh memakai validator Spring milik aplikasi:

```java
@Bean
public ValidationUtility validationUtility(jakarta.validation.Validator validator) {
    return ValidationConfig.builder()
            .useDefaultBehavior()
            .withValidator(validator)
            .useMessageDetails()
            .build();
}
```

### A.5. Membuat custom validation processor

Gunakan custom processor ketika aplikasi memerlukan aturan pembentukan exception,
logging, atau pengelompokan violation yang berbeda dari default. Buat class yang
extends `BaseValidationProcessor`, lalu implementasikan kedua jalur violation:

```java
import jakarta.validation.ConstraintViolation;
import jakarta.validation.Validator;
import org.springframework.http.HttpStatus;
import reyga.starter.foundation.core.exception.ValidationFaultException;
import reyga.starter.foundation.core.validation.BaseValidationProcessor;

import java.util.LinkedHashMap;
import java.util.Set;
import java.util.stream.Collectors;

public final class ApplicationValidationProcessor extends BaseValidationProcessor {

    public ApplicationValidationProcessor(Validator validator) {
        super(validator);
    }

    @Override
    protected <T> void violationsSetHandle(Set<ConstraintViolation<T>> violations) {
        if (violations.isEmpty()) {
            return;
        }

        Set<String> messages = violations.stream()
                .map(ConstraintViolation::getMessage)
                .collect(Collectors.toCollection(java.util.LinkedHashSet::new));

        throw new ValidationFaultException(
                "400441", "Invalid Request", messages, HttpStatus.BAD_REQUEST);
    }

    @Override
    protected <T> void violationsMapHandle(Set<ConstraintViolation<T>> violations) {
        if (violations.isEmpty()) {
            return;
        }

        var errors = violations.stream()
                .map(violation -> {
                    var detail = new LinkedHashMap<String, Object>();
                    detail.put("field", violation.getPropertyPath().toString());
                    detail.put("message", violation.getMessage());
                    return detail;
                })
                .toList();

        throw new ValidationFaultException(
                "400441", "Invalid Request", errors, HttpStatus.BAD_REQUEST);
    }
}
```

Daftarkan processor tersebut melalui builder:

```java
@Bean
public ValidationUtility validationUtility(Validator validator) {
    return ValidationConfig.builder()
            .withProcessor(new ApplicationValidationProcessor(validator))
            .useMapDetails()
            .build();
}
```

`useMapDetails()` memanggil `violationsMapHandle()`, sedangkan
`useMessageDetails()` memanggil `violationsSetHandle()`. Custom processor harus
tidak menyimpan object request antar-pemanggilan dan harus aman digunakan oleh
singleton bean. Jika processor melempar `ValidationFaultException`, tetap aktifkan
`validation-handler: true`. Jika memakai exception lain, aplikasi perlu
menyediakan `@RestControllerAdvice` yang sesuai.

### A.6. Validation groups

```java
public interface CreateValidationGroup {}
public interface UpdateValidationGroup {}
```

Groups dapat ditetapkan pada bean atau pada satu pemanggilan:

```java
return ValidationConfig.builder()
        .useDefaultBehavior()
        .withValidationGroups(CreateValidationGroup.class)
        .build();
```

```java
validationUtility.validateRequest(request);
validationUtility.validateRequest(
        request,
        java.util.List.of(UpdateValidationGroup.class)
);
```

Groups eksplisit pada method menggantikan groups dari konfigurasi. Daftar kosong
memilih Jakarta group `Default`. Setiap group harus berupa interface dan tidak
boleh `null`.

### A.7. Anotasi validation

Library menyediakan empat anotasi validation: `@FieldPresence`, `@FieldFormat`,
`@FieldLength`, dan `@FieldNumberRange`. Atribut `message`, `groups`, dan
`payload` mengikuti kontrak Jakarta Bean Validation.

#### `@FieldPresence`

Mengatur null dan nilai kosong secara independen untuk seluruh tipe field.

| Atribut | Default | Kegunaan |
|---|---:|---|
| `nullable` | `false` | Menentukan apakah referensi `null` diterima. |
| `allowBlank` | `false` | Menentukan apakah nilai non-null yang kosong diterima. |
| `message` | Pesan bawaan constraint | Pesan ketika validasi gagal. |

```java
@FieldPresence(
        nullable = false,
        allowBlank = false,
        message = "customerId wajib diisi"
)
private UUID customerId;
```

| `nullable` | `allowBlank` | `null` | Nilai kosong | Nilai terisi |
|---:|---:|---|---|---|
| `false` | `false` | Ditolak | Ditolak | Diterima |
| `false` | `true` | Ditolak | Diterima | Diterima |
| `true` | `false` | Diterima | Ditolak | Diterima |
| `true` | `true` | Diterima | Diterima | Diterima |

Nilai kosong mencakup `CharSequence` kosong/whitespace, collection atau map
kosong, array dengan panjang nol, dan `Optional` kosong. Angka `0`, boolean
`false`, UUID, tanggal, enum, dan object non-null lain dianggap terisi. Untuk
memvalidasi isi object bertingkat gunakan `@Valid`; untuk isi container, pasang
constraint pada tipe elemennya.

```java
@FieldPresence
private java.util.List<@FieldPresence String> names;
```

#### `@FieldFormat`

Memvalidasi format `String` dan `Number`. Object `UUID` hanya didukung ketika
`formatType = FieldFormatTypeEnum.UUID`.

| Atribut | Default | Kegunaan |
|---|---:|---|
| `fieldName` | String kosong | Nama field pada pesan default. |
| `formatType` | `ALLOW_ALL` | Memilih kebijakan format bawaan. |
| `customFormat` | String kosong | Regex aplikasi yang menggantikan format bawaan. |
| `onlyContains` | Array kosong | Allow-list untuk representasi teks. |
| `onlyNumbers` | Array kosong | Allow-list untuk nilai angka. |
| `message` | String kosong | Mengganti pesan error bawaan processor. |

```java
@FieldPresence(message = "email wajib diisi")
@FieldFormat(
        fieldName = "email",
        formatType = FieldFormatTypeEnum.EMAIL,
        message = "Format email tidak valid"
)
private String email;
```

| `FieldFormatTypeEnum` | Format yang diterima |
|---|---|
| `UUID` | UUID kanonis `8-4-4-4-12`; versi 1-8 dengan RFC variant, Nil UUID, atau Max UUID. Nilai dapat berupa `String` atau `java.util.UUID`. |
| `DATE` | Tanggal kalender valid dengan format `yyyy-MM-dd`. |
| `IP_ADDRESS` | IPv4 dengan empat octet `0` sampai `255`. |
| `EMAIL` | Alamat email ASCII dengan local-part dan domain yang valid. |
| `PHONE_NUMBER` | Nomor dengan digit, spasi/minus, kurung, dan prefix `+` opsional. |
| `LETTER_ONLY` | Huruf ASCII `A-Z` atau `a-z`. |
| `ALPHANUMERIC` | Huruf ASCII dan digit. |
| `NUMERIC_ONLY` | Digit ASCII tanpa tanda atau pecahan. |
| `PASSWORD_STRONG` | Minimal delapan karakter, memuat huruf besar, huruf kecil, angka, dan tanda baca. |
| `ALLOW_ALL` | Menerima seluruh representasi teks yang didukung. |

Atribut tambahan:

- `customFormat` menggantikan regex format bawaan;
- `onlyContains` membatasi nilai teks ke allow-list;
- `onlyNumbers` membatasi nilai angka secara exact, tanpa pemotongan pecahan;
- `fieldName` digunakan pada pesan default.

`@FieldFormat` menolak `null`; kombinasikan aturan presence dan format sesuai
kebutuhan. Nilai tidak di-trim ketika format diperiksa. Regex pada
`customFormat` harus berasal dari konfigurasi terpercaya dan valid.

Untuk request JSON dengan field bertipe `UUID`, nilai yang tidak valid ditolak
oleh deserializer sebelum Jakarta Validation berjalan. Gunakan field `String`
jika aplikasi ingin seluruh kesalahan teks UUID diproses oleh `@FieldFormat`,
kemudian konversikan menjadi `UUID` setelah validasi berhasil.

#### `@FieldLength`

Memvalidasi panjang `String` atau jumlah digit pada `Number`. Batas `min` dan
`max` bersifat inklusif. Nilai `null` diterima, sehingga gunakan
`@FieldPresence` jika field wajib diisi.

| Atribut | Default | Kegunaan |
|---|---:|---|
| `fieldName` | String kosong | Nama field pada pesan default. |
| `min` | `0` | Panjang minimum yang diterima. |
| `max` | `Long.MAX_VALUE` | Panjang maksimum yang diterima. |
| `message` | String kosong | Mengganti pesan error bawaan processor. |

```java
@FieldPresence
@FieldLength(
        fieldName = "customerName",
        min = 3,
        max = 100,
        message = "Nama harus memiliki 3 sampai 100 karakter"
)
private String customerName;
```

Gunakan anotasi ini pada `String` atau tipe `Number`. Untuk collection atau array,
gunakan constraint Jakarta yang sesuai.

#### `@FieldNumberRange`

Memvalidasi nilai `Number` dalam rentang `min` sampai `max` secara inklusif.
Nilai `null` diterima.

| Atribut | Default | Kegunaan |
|---|---:|---|
| `fieldName` | String kosong | Nama field pada pesan default. |
| `min` | `Long.MIN_VALUE` | Nilai minimum yang diterima. |
| `max` | `Long.MAX_VALUE` | Nilai maksimum yang diterima. |
| `message` | String kosong | Mengganti pesan error bawaan processor. |

```java
@FieldPresence
@FieldNumberRange(
        fieldName = "retryCount",
        min = 1,
        max = 5,
        message = "Retry count harus berada pada rentang 1 sampai 5"
)
private Integer retryCount;
```

Gunakan anotasi ini untuk tipe angka integral. Jika bisnis membutuhkan presisi
pecahan, gunakan constraint decimal Jakarta atau validator aplikasi yang sesuai.

### A.8. Validation group pada anotasi

```java
@FieldPresence(
        groups = CreateValidationGroup.class,
        message = "ID wajib diisi"
)
@FieldFormat(
        fieldName = "id",
        formatType = FieldFormatTypeEnum.UUID,
        groups = CreateValidationGroup.class
)
private String id;
```

Constraint hanya dijalankan ketika group yang sesuai diberikan kepada
`ValidationUtility` atau Spring MVC `@Validated`.

## B. Resilience Utils

### B.1. Mengaktifkan bean dan fitur

`ResilienceService` menyediakan satu facade untuk rate limiter, circuit breaker,
dan retry. Aktifkan default utilities dan hanya fitur resilience yang digunakan:

Dependency Resilience4j tersedia secara transitif melalui module `core`.
Consumer yang memilih bundle seluruh dependency produksi dapat menggunakan
`foundation-dependencies`; tidak diperlukan deklarasi `resilience4j-all`
terpisah.

```yaml
reyga:
  config:
    default-bean:
      utilities: true
    rate-limiter:
      required: true
      timeout-milis: 500
      max-request: 100
      refresh-period-seconds: 1
    circuit-breaker:
      required: true
      failure-rate-threshold: 50
      slow-call-rate-threshold: 50
      slow-call-duration-threshold-seconds: 2
      minimum-number-of-calls: 10
      sliding-window-size: 20
      permitted-number-of-calls-in-half-open-state: 5
      wait-duration-in-open-state-seconds: 30
      automatic-transition-from-open-to-half-open-enabled: true
    retry:
      required: true
      max-attempts: 3
      wait-duration-millis: 500
      fail-after-max-attempts: true
```

`utilities: true` menyediakan `ResilienceService` dan `TransactionalExecutor`.
Setiap `required: true` menyediakan config dan registry fitur terkait. Karena
`TransactionalExecutor` juga dibuat, aplikasi harus mempunyai
`PlatformTransactionManager`.

### B.2. Rate limiter

Rate limiter membatasi eksekusi berdasarkan key. Fallback dijalankan ketika
permission tidak tersedia.

```java
@Service
@RequiredArgsConstructor
public class NotificationGateway {
    private final ResilienceService resilienceService;
    private final RateLimiterConfig rateLimiterConfig;
    private final RateLimiterRegistry rateLimiterRegistry;

    public NotificationResponse send(NotificationRequest request) {
        return resilienceService.useRateLimiter(
                rateLimiterConfig,
                rateLimiterRegistry,
                "notification-send",
                () -> sendToProvider(request),
                () -> NotificationResponse.rateLimited()
        );
    }
}
```

Gunakan key yang stabil dan berbeda untuk setiap kebijakan. Overload
`useRateLimiterWithCache(...)` menerima Spring `Cache`; yang disimpan adalah
instance rate limiter berdasarkan key, bukan hasil proses bisnis. Jika cache
tidak dapat membaca atau menyimpan instance tersebut, utility tetap menggunakan
registry.

### B.3. Circuit breaker

Circuit breaker menjalankan fallback saat proses utama gagal atau circuit tidak
mengizinkan pemanggilan.

```java
return resilienceService.useCircuitBreaker(
        circuitBreakerConfig,
        circuitBreakerRegistry,
        "customer-provider",
        () -> customerClient.findById(customerId),
        () -> CustomerResponse.unavailable(customerId)
);
```

Nama circuit menentukan instance dan kumpulan metrik yang digunakan. Fallback
harus aman, cepat, dan tidak mengulang operasi utama tanpa batas.

### B.4. Retry

Retry mengulang proses berdasarkan `RetryConfig`. Setelah seluruh attempt gagal,
exception terakhir diteruskan kepada caller.

```java
return resilienceService.useRetry(
        retryConfig,
        retryRegistry,
        "customer-read",
        () -> customerClient.findById(customerId)
);
```

Gunakan retry hanya untuk operasi yang aman diulang, seperti read atau write yang
mempunyai idempotency key. `max-attempts` mencakup pemanggilan pertama. Library
juga menyediakan overload `Runnable` untuk proses tanpa return value.

### B.5. Resilience pada controller

`ResilienceBaseController` menyediakan helper response untuk rate limiter dan
circuit breaker. Class ini membutuhkan `ResilienceService`,
`RateLimiterRegistry`, dan `CircuitBreakerRegistry` pada constructor. Karena itu,
aktifkan kedua registry jika controller meng-extend class tersebut, walaupun satu
endpoint hanya memakai rate limiter.

Contoh implementasi controller tersedia pada
[Panduan Implementasi Controller](%281.0.0%29%20CONTROLLER_IMPLEMENTATION_GUIDE.md#contoh-rate-limiter-menggunakan-config-yaml).

## C. Transactional Utility

`TransactionalExecutor` menjalankan `Supplier` atau `Runnable` di dalam transaksi
Spring dan menyediakan fallback ketika proses melempar exception.

```java
@Service
@RequiredArgsConstructor
public class PaymentService {
    private final TransactionalExecutor transactionalExecutor;

    public PaymentResult save(Payment payment) {
        return transactionalExecutor.runInTransaction(
                () -> savePaymentAndLedger(payment),
                error -> PaymentResult.failed(error.getMessage())
        );
    }
}
```

Ketika proses utama gagal, transaksi ditandai rollback lalu fallback menerima
error tersebut. Nilai yang dikembalikan fallback menjadi hasil method. Overload
`Runnable` menerima `Consumer<Throwable>` sebagai fallback.

Aktifkan bean dengan `reyga.config.default-bean.utilities: true` dan pastikan
aplikasi menyediakan `PlatformTransactionManager`.

## D. Date Utility

`DateUtility` menyediakan operasi tanggal stateless, antara lain waktu UTC/waktu
system, konversi `Date`, `Timestamp`, `LocalDate`, dan `LocalDateTime`, parsing,
formatting, serta batas awal/akhir hari, minggu, dan bulan.

Konstanta `DateUtility.DEFAULT_TIMEZONE_ID` bernilai `UTC` dan dapat dipakai
ketika aplikasi memerlukan identifier timezone default yang sama dengan library.

```java
LocalDateTime utcNow = DateUtility.now();
LocalDate invoiceDate = DateUtility.parseLocalDate("2026-09-11", "yyyy-MM-dd");
String label = DateUtility.format(invoiceDate, "dd MMMM yyyy", new Locale("id", "ID"));
LocalDate monthEnd = DateUtility.getEndOfMonth(invoiceDate);
```

`now()` menggunakan UTC, sedangkan method dengan suffix `SystemTimezone`
menggunakan timezone JVM. Tetapkan timezone aplikasi secara konsisten agar hasil
tidak berbeda antar-environment. Parsing yang gagal melempar
`DateTimeParseException`; gunakan `isValidDate()` jika hanya membutuhkan hasil
boolean.

## E. File Utility

`FileUtility` menyediakan wrapper berbasis `java.nio.file.Path` untuk normalisasi,
informasi nama file, read/write, copy/move, pembuatan directory, listing, delete,
dan masking nama file.

```java
Path report = FileUtility.toPath("reports/daily.csv");
FileUtility.ensureParentDirectory(report);
FileUtility.writeString(report, "id,total\n1,1000");

String extension = FileUtility.extension(report);       // csv
String safeName = FileUtility.maskFileName("customer.csv");
```

Read/write string menggunakan UTF-8 jika charset tidak diberikan. Operasi I/O
dapat melempar `IOException`; aplikasi tetap bertanggung jawab melakukan
otorisasi path, membatasi lokasi akses, dan menentukan opsi overwrite. Jangan
gunakan path langsung dari request tanpa validasi dan pembatasan directory.

## F. Mapper

### F.1. Menyiapkan MapStruct

`BaseMapper<E, D>` merupakan kontrak umum untuk mapping entity dan DTO, sedangkan
`CommonMapperConfig` menyediakan konfigurasi MapStruct yang konsisten untuk
aplikasi Spring. Implementasi mapper dibuat otomatis oleh MapStruct pada saat
kompilasi, sehingga annotation processing harus aktif pada project pengguna.

Contoh konfigurasi Gradle:

```kotlin
dependencies {
    implementation("com.reyga-dev.starter:common:1.0.0")
    implementation("org.mapstruct:mapstruct:1.6.3")
    annotationProcessor("org.mapstruct:mapstruct-processor:1.6.3")
}
```

Contoh konfigurasi Maven:

```xml
<properties>
    <org.mapstruct.version>1.6.3</org.mapstruct.version>
</properties>

<dependencies>
    <dependency>
        <groupId>com.reyga-dev.starter</groupId>
        <artifactId>common</artifactId>
        <version>1.0.0</version>
    </dependency>
    <dependency>
        <groupId>org.mapstruct</groupId>
        <artifactId>mapstruct</artifactId>
        <version>${org.mapstruct.version}</version>
    </dependency>
</dependencies>

<build>
    <plugins>
        <plugin>
            <groupId>org.apache.maven.plugins</groupId>
            <artifactId>maven-compiler-plugin</artifactId>
            <configuration>
                <annotationProcessorPaths>
                    <path>
                        <groupId>org.mapstruct</groupId>
                        <artifactId>mapstruct-processor</artifactId>
                        <version>${org.mapstruct.version}</version>
                    </path>
                </annotationProcessorPaths>
            </configuration>
        </plugin>
    </plugins>
</build>
```

Gunakan versi MapStruct yang kompatibel dengan versi library. Jika project juga
menggunakan Lombok, tambahkan annotation processor Lombok dan
`lombok-mapstruct-binding` sesuai konfigurasi build project tersebut.

### F.2. Membuat mapper

Buat interface mapper, beri anotasi `@Mapper`, lalu extend `BaseMapper` dengan
urutan generic `<Entity, DTO>`.

```java
import org.mapstruct.Mapper;
import reyga.starter.foundation.common.mapper.BaseMapper;
import reyga.starter.foundation.common.mapper.CommonMapperConfig;

@Mapper(config = CommonMapperConfig.class)
public interface CustomerMapper extends BaseMapper<Customer, CustomerDto> {
}
```

Interface tersebut memperoleh kontrak berikut:

| Method | Behavior |
|---|---|
| `toDto(E entity)` | Mengubah satu entity menjadi DTO |
| `toEntity(D dto)` | Mengubah satu DTO menjadi entity |
| `toDtoList(List<E> entities)` | Mengubah list entity menjadi list DTO |
| `toEntityList(List<D> dtos)` | Mengubah list DTO menjadi list entity |
| `updateEntity(D dto, E entity)` | Memetakan nilai DTO ke instance entity yang diberikan |

Jika nama dan tipe property sama, MapStruct dapat membuat mapping tanpa method
tambahan. Untuk property yang berbeda, override kontrak yang diperlukan dan
tambahkan anotasi mapping.

```java
import org.mapstruct.Mapping;

@Mapper(config = CommonMapperConfig.class)
public interface CustomerMapper extends BaseMapper<Customer, CustomerDto> {

    @Override
    @Mapping(target = "fullName", source = "name")
    CustomerDto toDto(Customer entity);

    @Override
    @Mapping(target = "name", source = "fullName")
    Customer toEntity(CustomerDto dto);
}
```

`CommonMapperConfig` menerapkan behavior berikut pada seluruh mapper yang
menggunakannya:

- implementasi mapper didaftarkan sebagai Spring bean;
- dependency mapper lain di-inject melalui constructor;
- target property yang belum dipetakan menyebabkan compilation error; dan
- pemeriksaan `null` selalu dibuat pada mapping yang memerlukannya.

Compilation error untuk target yang belum dipetakan membantu mencegah field baru
terlewat tanpa sengaja. Petakan field tersebut dengan `@Mapping`, atau gunakan
`@Mapping(target = "fieldName", ignore = true)` jika memang tidak dibutuhkan.

### F.3. Menggunakan mapper pada service

Karena mapper yang memakai `CommonMapperConfig` menjadi Spring bean, inject
interface mapper melalui constructor. Jangan membuat instance mapper secara
manual.

```java
import org.springframework.stereotype.Service;

@Service
public class CustomerService {

    private final CustomerRepository customerRepository;
    private final CustomerMapper customerMapper;

    public CustomerService(
            CustomerRepository customerRepository,
            CustomerMapper customerMapper
    ) {
        this.customerRepository = customerRepository;
        this.customerMapper = customerMapper;
    }

    public CustomerDto findById(UUID id) {
        Customer customer = customerRepository.findById(id)
                .orElseThrow(() -> new CustomerNotFoundException(id));
        return customerMapper.toDto(customer);
    }

    public List<CustomerDto> findAll() {
        return customerMapper.toDtoList(customerRepository.findAll());
    }

    public CustomerDto update(UUID id, CustomerDto request) {
        Customer customer = customerRepository.findById(id)
                .orElseThrow(() -> new CustomerNotFoundException(id));
        customerMapper.updateEntity(request, customer);
        return customerMapper.toDto(customerRepository.save(customer));
    }
}
```

Untuk request partial update, deklarasikan behavior `null` secara eksplisit pada
method update agar field entity yang tidak dikirim tidak tertimpa.

```java
import org.mapstruct.BeanMapping;
import org.mapstruct.MappingTarget;
import org.mapstruct.NullValuePropertyMappingStrategy;

@Override
@BeanMapping(nullValuePropertyMappingStrategy = NullValuePropertyMappingStrategy.IGNORE)
void updateEntity(CustomerDto dto, @MappingTarget Customer entity);
```

Pisahkan DTO berdasarkan kebutuhan jika kontrak create, update, dan response
memiliki bentuk berbeda. Dalam kondisi tersebut, mapper dapat mendeklarasikan
method tambahan di luar kontrak `BaseMapper`.

### F.4. Mapper Utility untuk diagnostic

`MapperUtility.convertDtoToJsonString()` membuat representasi teks field DTO,
terutama untuk diagnostic atau logging. Overload kedua dapat menyertakan field
dari superclass dan menangani object bertingkat, collection, array, map, serta
circular reference.

```java
String requestDetail = MapperUtility.convertDtoToJsonString(request, true);
```

Utility ini memakai reflection dan bukan pengganti serializer JSON untuk kontrak
API atau persistence. Hindari menggunakannya pada object yang berisi password,
token, data pribadi, atau field sensitif lain karena nilai field dapat ikut
tercetak.

## G. File Inspector

`FileInspector` memakai Apache Tika untuk mendeteksi content type, mengekstrak
teks, memperoleh hasil ekstraksi sebagai `Reader`, dan menerjemahkan teks.
`foundation-starter` menyediakan bean default secara otomatis, sehingga tidak
memerlukan feature flag tambahan.

```java
import lombok.RequiredArgsConstructor;
import org.apache.tika.metadata.Metadata;
import org.springframework.stereotype.Service;
import reyga.starter.foundation.common_io.operations.FileInspector;

import java.io.InputStream;

@Service
@RequiredArgsConstructor
public class DocumentInspectionService {

    private final FileInspector fileInspector;

    public InspectedDocument inspect(InputStream inputStream, String fileName) {
        Metadata metadata = new Metadata();
        metadata.set(Metadata.RESOURCE_NAME_KEY, fileName);

        String contentType = fileInspector.checkContentType(inputStream, metadata);
        return new InspectedDocument(contentType, metadata);
    }
}
```

Pilih overload berdasarkan sumber yang tersedia:

| Kebutuhan | Method utama | Sumber yang didukung |
|---|---|---|
| Deteksi content type | `checkContentType(...)` | `InputStream`, `byte[]`, `File`, `Path`, nama file, atau `URL` |
| Ekstraksi langsung menjadi teks | `extractContent(...)` | `InputStream`, `URL`, `File`, atau `Path` |
| Ekstraksi streaming | `extract(...)` | `InputStream`, `URL`, `File`, atau `Path` |
| Terjemahan teks | `translate(...)` | Teks dengan target language, atau source dan target language |

Gunakan overload `checkContentType(InputStream, String)` atau
`checkContentType(InputStream, Metadata)` ketika nama file atau metadata dapat
membantu Tika membedakan format. `checkContentType(String)` hanya menerima nama
file dan tidak membaca isi file. Nilai yang dikembalikan berupa media type,
misalnya `application/pdf` atau `image/png`.

Untuk dokumen besar, gunakan
`extractContent(InputStream, Metadata, int maxLength)` agar jumlah karakter hasil
dibatasi. Method `extract(...)` mengembalikan `Reader`; caller harus membaca dan
menutup `Reader` tersebut. Caller juga tetap bertanggung jawab atas lifecycle
`InputStream` yang diberikan.

```java
Metadata metadata = new Metadata();
String preview = fileInspector.extractContent(inputStream, metadata, 10_000);

try (Reader reader = fileInspector.extract(path)) {
    // Proses hasil ekstraksi secara streaming.
}
```

Fitur `translate(...)` memerlukan implementasi translator Apache Tika yang
tersedia pada runtime. Kegagalan deteksi, ekstraksi, atau terjemahan dibungkus
sebagai `IOFaultException` dengan operasi seperti `DETECT_CONTENT_TYPE`,
`PARSE_TO_STRING`, `PARSE`, atau `TRANSLATE`.

Deteksi content type membantu validasi upload, tetapi tidak menggantikan batas
ukuran, allow-list media type, pemeriksaan malware, dan pembatasan lokasi file.

## H. File Sanitizer

`FileSanitizer` menyediakan sanitasi HTML serta pemeriksaan indikasi XSS dan SQL
injection. Bean default tersedia otomatis dari `foundation-starter` tanpa
feature flag tambahan. Overload tanpa charset memakai UTF-8.

### H.1. Sanitasi HTML dan pemeriksaan XSS

```java
String safeHtml = fileSanitizer.sanitizeHtml(untrustedHtml);

if (fileSanitizer.checkXssPayload(untrustedHtml)) {
    throw new IllegalArgumentException("HTML mengandung elemen yang tidak diizinkan");
}
```

Policy default OWASP menggabungkan policy `FORMATTING`, `BLOCKS`, `LINKS`,
`IMAGES`, dan `STYLES`. Gunakan overload `PolicyFactory` ketika aplikasi
memerlukan allow-list HTML yang berbeda.

```java
PolicyFactory policy = Sanitizers.FORMATTING.and(Sanitizers.LINKS);
String safeHtml = fileSanitizer.sanitizeHtml(untrustedHtml, policy);
```

`sanitizeHtml(...)` mengembalikan HTML yang sudah disaring.
`checkXssPayload(...)` membandingkan input dengan hasil sanitasi dan
mengembalikan `true` jika policy mengubah input. Karena hasil tersebut mengikuti
policy yang dipakai, method ini merupakan pemeriksaan perubahan oleh sanitizer,
bukan klasifikasi seluruh kemungkinan serangan XSS.

Semua kelompok method sanitasi dan XSS mempunyai overload untuk `String`,
`byte[]`, `InputStream`, `Path`, `File`, dan `URL`. Caller mengelola lifecycle
`InputStream`; stream yang dibuka sendiri dari `URL` ditutup oleh implementasi.

### H.2. Pemeriksaan SQL injection

```java
boolean suspicious = fileSanitizer.checkSqlInjection(userInput);

Pattern applicationPattern = Pattern.compile(
        "(?i)\\bcopy\\b.+\\bto\\s+program\\b"
);
boolean matchesApplicationRule = fileSanitizer.checkSqlInjection(
        userInput,
        applicationPattern
);
```

Overload tanpa pattern memakai kumpulan pattern bawaan. Overload yang menerima
`Pattern...` atau `List<Pattern>` hanya memeriksa pattern non-null yang diberikan;
gabungkan pattern bawaan di sisi aplikasi jika keduanya diperlukan. Input juga
dapat berasal dari `byte[]`, `InputStream`, `Path`, `File`, atau `URL`.

Pemeriksaan ini berbasis regular expression dan dapat menghasilkan false
positive atau false negative. Gunakan prepared statement atau parameter binding
sebagai perlindungan utama query database; jangan membangun SQL dengan
concatenation walaupun pemeriksaan mengembalikan `false`.

Input `null`, kegagalan membaca sumber, atau policy yang tidak valid menghasilkan
`IOFaultException`. Metadata exception mencatat operasi `SANITIZE`, `CHECK_XSS`,
atau `CHECK_SQL`, permission `READ_ONLY`, storage type sumber, dan charset.

## I. Report Builder

`ReportBuilder` menyediakan staged fluent API untuk compile JRXML, mengisi
parameter dan data, lalu mengekspor hasil JasperReports. Urutan tahap dijaga oleh
return type API: `CompileStep` menghasilkan `FillStep`, dan `FillStep`
menghasilkan `ExportStep`.

```java
import net.sf.jasperreports.engine.data.JRBeanCollectionDataSource;
import reyga.starter.foundation.common_io.enumeration.ReportType;
import reyga.starter.foundation.common_io.reports.ReportBuilder;

Map<String, Object> parameters = Map.of(
        "REPORT_TITLE", "Laporan Transaksi"
);

byte[] pdf = ReportBuilder
        .from("reports/transaction.jrxml")
        .compile()
        .withParameters(parameters)
        .withLocale(new Locale("id", "ID"))
        .withTimeZone(TimeZone.getTimeZone("Asia/Jakarta"))
        .withDataSource(new JRBeanCollectionDataSource(rows))
        .fill()
        .exportTo(ReportType.PDF);
```

Sumber JRXML dapat berupa `InputStream`, path `String`, atau `JasperDesign`.
Overload `InputStream` membaca seluruh source ke memory dan dapat melempar
`IOException`; compile, fill, dan export dapat melempar `JRException`.

Pada tahap fill, gunakan salah satu sumber data berikut:

- `withDataSource(JRDataSource)` untuk collection atau data source Jasper;
- `withConnection(Connection)` untuk report yang menjalankan query melalui JDBC;
- tanpa keduanya untuk memakai `JREmptyDataSource`.

Jika data source dan connection sama-sama diberikan, connection diprioritaskan.
Lifecycle `Connection` tetap menjadi tanggung jawab caller. Parameter dari
beberapa pemanggilan `withParameters(...)` digabung; key terakhir menggantikan
nilai sebelumnya. `withLocale(...)` dan `withTimeZone(...)` mengisi parameter
bawaan JasperReports.

```java
try (OutputStream outputStream = Files.newOutputStream(target)) {
    ReportBuilder.from(jrxmlInputStream)
            .compile()
            .withConnection(connection)
            .fill()
            .exportTo(ReportType.XLSX, outputStream);
}
```

Format yang didukung langsung adalah `HTML`, `PDF`, `XLS`, `XLSX`, `CSV`,
`DOCX`, `PPTX`, `RTF`, `ODT`, `ODS`, `XML`, `JSON`, `TEXT`, dan `JRPRINT`.
`ODP`, `PNG`, `JPEG`, `GIF`, dan `SVG` sudah tersedia pada enum `ReportType`,
tetapi exporter-nya belum disediakan dan akan menghasilkan `JRException`.
Gunakan `ReportType.getExtension()` dan `getMimeType()` untuk nama file serta
header response.

```java
ReportType type = ReportType.PDF;
return ResponseEntity.ok()
        .contentType(MediaType.parseMediaType(type.getMimeType()))
        .header(
                HttpHeaders.CONTENT_DISPOSITION,
                "attachment; filename=report." + type.getExtension()
        )
        .body(pdf);
```

Implementasi builder ditemukan melalui `ReportBuilderProvider` dan Java
`ServiceLoader`. Pastikan dependency runtime `foundation-starter` tersedia;
memakai API `common-io` tanpa provider menghasilkan `IllegalStateException`.
Satu instance builder menyimpan state compile, parameter, data source, dan hasil
fill, sehingga buat instance baru untuk setiap pembuatan report dan jangan
memakainya bersama antar-thread.

## J. `IOFaultException` dan metadata

`IOFaultException` adalah runtime exception untuk kegagalan operasi file atau
content. Exception dapat membawa satu `IOFaultMetadata`, daftar metadata untuk
operasi multi-file, dan cause asli.

```java
IOFaultMetadata metadata = IOFaultMetadata.builder()
        .fileName(uploadedFile.getOriginalFilename())
        .mimeType(MediaType.APPLICATION_PDF)
        .charset(StandardCharsets.UTF_8.name())
        .operation(IOOperation.VALIDATE)
        .permissions(IOPermissions.READ_ONLY)
        .storageType(IOStorageType.MEMORY)
        .sizeBytes(uploadedFile.getSize())
        .build();

throw new IOFaultException(
        "Dokumen upload tidak valid",
        metadata,
        cause
);
```

Constructor yang tersedia:

| Constructor | Penggunaan |
|---|---|
| `IOFaultException(message)` | Error tanpa metadata dan cause |
| `IOFaultException(message, cause)` | Error dengan cause asli |
| `IOFaultException(message, metadata)` | Error untuk satu resource |
| `IOFaultException(message, metadata, cause)` | Error satu resource dengan cause |
| `IOFaultException(message, metadataList)` | Error untuk beberapa resource |
| `IOFaultException(message, metadataList, cause)` | Error beberapa resource dengan cause |

Field `IOFaultMetadata` berikut dapat diisi sesuai konteks operasi:

| Field | Isi yang diharapkan |
|---|---|
| `fileName` | Nama file tanpa mengandalkan nilai ini sebagai path tepercaya |
| `filePath` | Path sumber atau target pada storage |
| `uri` | URI resource lokal atau remote |
| `mimeType` | Media type resource sebagai Spring `MediaType` |
| `charset` | Nama charset, misalnya `UTF-8` |
| `operation` | Nilai `IOOperation`, misalnya `READ`, `WRITE`, `SANITIZE`, atau `VALIDATE` |
| `permissions` | Mode akses dari `IOPermissions` |
| `storageType` | Lokasi storage dari `IOStorageType`, misalnya `LOCAL`, `MEMORY`, `S3`, atau `HTTPS` |
| `checksum` | Checksum resource jika tersedia |
| `directory` | Menandai apakah resource merupakan directory |
| `sizeBytes` | Ukuran resource dalam byte |
| `lastModifiedEpochMillis` | Waktu modifikasi terakhir dalam epoch millisecond |
| `offset` | Posisi awal bagian data yang gagal |
| `length` | Panjang bagian data yang gagal |

Enum `IOOperation` juga mencakup operasi file umum seperti `COPY`, `MOVE`,
`DELETE`, `CREATE`, `LIST`, dan `METADATA`. Pilih nilai yang menggambarkan operasi
yang benar-benar gagal agar diagnostic tetap akurat.

Handler bawaan `DefaultAppValidationExceptionHandler` menangani exception ini
sebagai HTTP `400 Bad Request` dengan service code file error. Satu metadata dan
seluruh isi `metadataList` diubah menjadi detail file. Response hanya memuat nama
file yang sudah di-mask, operation, MIME type, charset, flag directory, ukuran,
waktu modifikasi, offset, dan length. Field internal seperti path, URI,
permission, storage type, dan checksum tidak dimasukkan ke response tersebut.

Jangan mengisi message atau metadata dengan isi file, credential, token, atau
path sensitif yang tidak boleh masuk log. Sertakan cause ketika membungkus
exception agar root cause tetap tersedia untuk diagnostic internal.

## K. Aspect Advice

Aspect Advice menjalankan behavior aplikasi pada titik tertentu dalam lifecycle
method. Setiap advice memakai anotasi, base behavior, flag aktivasi, dan nama
bean behavior yang terpisah. Karena itu, aplikasi dapat mengaktifkan hanya advice
yang diperlukan.

Dependency `spring-boot-starter-aspectj` sudah dipublikasikan secara transitif
melalui module `core`. Aplikasi pengguna tidak perlu menambahkan Spring AOP atau
AspectJ secara manual selama dependency transitif tersebut tidak dikecualikan.
Dependency tersebut juga tersedia melalui bundle opt-in
`foundation-dependencies` bersama seluruh dependency produksi pihak ketiga.

| Advice | Anotasi method | Base behavior | Waktu eksekusi |
|---|---|---|---|
| Around | `@AroundExecution` | `BaseAspectAround` | Mengendalikan lifecycle sebelum dan sesudah method target. |
| Before | `@BeforeExecution` | `BaseAspectBefore` | Tepat sebelum method target. |
| After | `@AfterExecution` | `BaseAspectAfter` | Setelah method target, baik sukses maupun gagal. |
| After Returning | `@AfterReturningExecution` | `BaseAspectAfterReturning` | Setelah method target sukses dan mengembalikan hasil. |
| After Throwing | `@AfterThrowingExecution` | `BaseAspectAfterThrowing` | Setelah method target melempar error. |

### K.1. Around advice

Around advice cocok untuk audit, pengukuran durasi, pengumpulan context, atau
tindakan lintas proses yang memerlukan akses ke seluruh lifecycle pemanggilan
method.

Flow penggunaannya adalah:

1. buat context yang extends `BaseContent`;
2. buat class behavior beranotasi `@Component` dan extends
   `BaseAspectAround`;
3. aktifkan `reyga.config.aspect.around`;
4. isi `reyga.config.aspect.behavior` dengan nama bean behavior; dan
5. tambahkan `@AroundExecution` pada method Spring bean yang ingin diproses.

#### K.1.1. Membuat context behavior

Context menyimpan data yang dibentuk sebelum method target berjalan dan dipakai
kembali oleh hook setelah eksekusi atau ketika terjadi exception. Context harus
extends `BaseContent`:

```java
public final class AuditContent extends BaseContent {
    private final long startedAtNanos = System.nanoTime();

    public long getStartedAtNanos() {
        return startedAtNanos;
    }
}
```

Buat context baru untuk setiap invocation. Jangan menyimpan context request pada
field singleton behavior karena satu bean dapat dipanggil beberapa thread secara
bersamaan.

#### K.1.2. Membuat behavior Around advice

Daftarkan behavior sebagai Spring bean dan extends `BaseAspectAround`. Pemberian
nama eksplisit pada `@Component` disarankan agar nilai YAML tidak bergantung pada
aturan penamaan default Spring:

```java
@Component("auditAspectBehavior")
public class AuditAspectBehavior extends BaseAspectAround<AuditContent> {

    private static final Logger log =
            LoggerFactory.getLogger(AuditAspectBehavior.class);

    @Override
    protected AuditContent preHandle() {
        return new AuditContent();
    }

    @Override
    protected void postHandle(AuditContent content) {
        long durationNanos = System.nanoTime() - content.getStartedAtNanos();
        log.info("Method completed in {} ns", durationNanos);
    }

    @Override
    protected boolean shouldHandleException() {
        return true;
    }

    @Override
    protected void handleException(
            Exception exception,
            AuditContent content
    ) {
        log.error("Intercepted method failed", exception);
    }
}
```

Hook yang tersedia:

| Hook | Waktu eksekusi | Tanggung jawab |
|---|---|---|
| `preHandle()` | Sebelum method target | Membuat context untuk satu invocation. |
| `postHandle(content)` | Pada blok `finally` setelah method target | Menutup lifecycle, mencatat durasi, atau menyimpan hasil akhir. |
| `shouldHandleException()` | Setelah method target melempar `Exception` | Menentukan apakah hook exception dijalankan. |
| `handleException(exception, content)` | Ketika exception terjadi dan hook diaktifkan | Melakukan logging, audit, atau tindakan error lain. |

`handleException(...)` tidak menggantikan exception. Setelah hook selesai,
exception dari method target tetap diteruskan kepada caller.

#### K.1.3. Mengaktifkan dan memilih behavior

Aktifkan Around Aspect dan isi nama bean behavior:

```yaml
reyga:
  config:
    aspect:
      around: true
      behavior: auditAspectBehavior
```

Nilai `behavior` harus sama persis dengan nama bean pada
`@Component("auditAspectBehavior")`. Jika nama pada `@Component` tidak ditulis,
Spring memakai nama class dengan huruf awal kecil. Sebagai contoh,
`AuditAspectBehavior` menjadi `auditAspectBehavior`.

Beberapa turunan `BaseAspectAround` boleh tersedia dalam Spring context. Library
hanya menjalankan bean yang dipilih melalui `reyga.config.aspect.behavior`:

```yaml
reyga:
  config:
    aspect:
      around: true
      behavior: paymentAuditBehavior
```

Untuk mengganti behavior pada environment lain, ubah nama bean pada property
tersebut tanpa mengubah anotasi method.

Jika fitur tidak digunakan, nonaktifkan flag dan kosongkan behavior:

```yaml
reyga:
  config:
    aspect:
      around: false
      behavior: ""
```

Ketika `around` bernilai `false`, bean dispatcher `AspectAround` tidak dibuat dan
`@AroundExecution` tidak mengubah eksekusi method.

#### K.1.4. Menandai method dengan `@AroundExecution`

Tambahkan anotasi pada method milik Spring bean:

```java
@Service
public class PaymentService {

    @AroundExecution
    public PaymentResponse process(PaymentRequest request) {
        // Jalankan proses bisnis.
        return new PaymentResponse();
    }
}
```

Method tanpa `@AroundExecution` tetap berjalan normal dan tidak memanggil
behavior:

```java
public PaymentStatus findStatus(String paymentId) {
    return repository.findStatus(paymentId);
}
```

Class target harus dikelola Spring, misalnya menggunakan `@Service`,
`@Component`, atau didaftarkan melalui `@Bean`. Pemanggilan method juga harus
melewati proxy Spring. Pemanggilan langsung dari satu method ke method lain pada
instance yang sama tidak memicu Around Aspect.

Untuk hasil yang konsisten, pasang `@AroundExecution` pada method implementasi
yang dipanggil, gunakan method non-final, dan panggil method melalui bean yang
di-inject oleh Spring.

#### K.1.5. Urutan lifecycle

Ketika method selesai dengan sukses:

```text
preHandle()
    -> method target
    -> postHandle(content)
    -> return value diteruskan kepada caller
```

Ketika method target melempar exception dan `shouldHandleException()`
mengembalikan `true`:

```text
preHandle()
    -> method target melempar exception
    -> shouldHandleException()
    -> handleException(exception, content)
    -> postHandle(content)
    -> exception diteruskan kepada caller
```

Jika `shouldHandleException()` mengembalikan `false`, tahap
`handleException(...)` dilewati tetapi `postHandle(...)` tetap dijalankan. Jika
`preHandle()` sendiri gagal, method target dan `postHandle(...)` belum dapat
dijalankan karena context belum berhasil dibuat.

#### K.1.6. Validasi konfigurasi saat startup

Ketika `around: true`, aplikasi dihentikan saat startup jika konfigurasi behavior
tidak valid. Hal ini mencegah aplikasi berjalan dengan anotasi yang terlihat
aktif tetapi tidak mempunyai implementasi behavior.

| Kondisi | Pesan dan tindakan perbaikan |
|---|---|
| `behavior` kosong | Isi `reyga.config.aspect.behavior` dengan nama bean behavior. |
| Bean tidak ditemukan | Pastikan package behavior masuk component scan dan nama YAML sama dengan nama bean. |
| Bean memiliki tipe yang salah | Pastikan class yang dipilih extends `BaseAspectAround`, bukan hanya bean biasa atau implementasi lain. |
| Behavior tidak terpanggil | Pastikan target merupakan Spring bean, method diberi `@AroundExecution`, method dipanggil melalui proxy, dan method tidak final. |
| Behavior yang salah terpanggil | Periksa nilai `reyga.config.aspect.behavior`; hanya bean dengan nama tersebut yang dipilih. |

### K.2. Before advice

Before advice dipakai untuk pemeriksaan akses, validasi kondisi, pencatatan awal,
atau menyiapkan data sebelum method target berjalan. Buat bean yang extends
`BaseAspectBefore`:

```java
@Component("authorizationBeforeBehavior")
public class AuthorizationBeforeBehavior extends BaseAspectBefore {

    @Override
    protected void beforeHandle(JoinPoint joinPoint) {
        String methodName = joinPoint.getSignature().toShortString();
        // Periksa akses atau catat awal eksekusi.
    }
}
```

Aktifkan behavior dan tandai method target:

```yaml
reyga:
  config:
    aspect:
      before: true
      before-behavior: authorizationBeforeBehavior
```

```java
@BeforeExecution
public PaymentResponse process(PaymentRequest request) {
    return paymentProcessor.process(request);
}
```

Jika `beforeHandle(...)` melempar exception, method target tidak dijalankan dan
exception diteruskan kepada caller.

### K.3. After advice

After advice selalu berjalan setelah method target selesai, seperti blok
`finally`. Advice ini cocok untuk membersihkan resource atau mencatat bahwa suatu
invocation sudah berakhir tanpa bergantung pada hasil akhirnya.

```java
@Component("cleanupAfterBehavior")
public class CleanupAfterBehavior extends BaseAspectAfter {

    @Override
    protected void afterHandle(JoinPoint joinPoint) {
        // Bersihkan context atau resource untuk invocation ini.
    }
}
```

```yaml
reyga:
  config:
    aspect:
      after: true
      after-behavior: cleanupAfterBehavior
```

```java
@AfterExecution
public void synchronizePayment() {
    paymentSynchronizer.synchronize();
}
```

`afterHandle(...)` dipanggil ketika method sukses maupun ketika method melempar
error. Gunakan After Returning atau After Throwing jika behavior hanya boleh
berjalan pada salah satu hasil tersebut.

### K.4. After Returning advice

After Returning advice hanya berjalan setelah method target sukses. Nilai yang
dikembalikan tersedia melalui parameter `result`.

```java
@Component("resultAuditBehavior")
public class ResultAuditBehavior extends BaseAspectAfterReturning {

    @Override
    protected void afterReturningHandle(JoinPoint joinPoint, Object result) {
        // Audit hasil tanpa mengubah nilai yang diterima caller.
    }
}
```

```yaml
reyga:
  config:
    aspect:
      after-returning: true
      after-returning-behavior: resultAuditBehavior
```

```java
@AfterReturningExecution
public PaymentStatus findStatus(String paymentId) {
    return paymentRepository.findStatus(paymentId);
}
```

Untuk method `void`, nilai `result` adalah `null`. Behavior ini mengamati hasil
yang dikembalikan dan tidak mengganti return value method target.

### K.5. After Throwing advice

After Throwing advice hanya berjalan ketika method target melempar error. Object
`Throwable` asli tersedia untuk logging, audit kegagalan, atau penambahan metric.

```java
@Component("failureAuditBehavior")
public class FailureAuditBehavior extends BaseAspectAfterThrowing {

    @Override
    protected void afterThrowingHandle(
            JoinPoint joinPoint,
            Throwable throwable
    ) {
        // Catat kegagalan tanpa menyimpan data sensitif.
    }
}
```

```yaml
reyga:
  config:
    aspect:
      after-throwing: true
      after-throwing-behavior: failureAuditBehavior
```

```java
@AfterThrowingExecution
public void cancelPayment(String paymentId) {
    paymentProcessor.cancel(paymentId);
}
```

Error dari method target tetap diteruskan kepada caller setelah behavior selesai.

### K.6. Konfigurasi lengkap dan aturan penggunaan

Semua advice dapat diaktifkan secara independen:

```yaml
reyga:
  config:
    aspect:
      around: true
      behavior: auditAspectBehavior
      before: true
      before-behavior: authorizationBeforeBehavior
      after: true
      after-behavior: cleanupAfterBehavior
      after-returning: true
      after-returning-behavior: resultAuditBehavior
      after-throwing: true
      after-throwing-behavior: failureAuditBehavior
```

Setiap flag bernilai `true` mewajibkan property behavior pasangannya terisi,
bean dengan nama tersebut tersedia di Spring context, dan class bean extends
base behavior yang sesuai. Aplikasi gagal saat startup jika salah satu aturan
tersebut tidak terpenuhi. Ketika sebuah flag bernilai `false`, dispatcher advice
tersebut tidak dibuat dan anotasinya tidak mengubah eksekusi method.

Satu method boleh memakai beberapa anotasi advice. Urutan relatif beberapa
advice pada method yang sama tidak dijamin oleh konfigurasi ini. Gunakan Around
advice ketika satu behavior membutuhkan urutan sebelum dan sesudah yang saling
terkait melalui context yang sama.

Seluruh advice hanya bekerja pada Spring bean yang dipanggil melalui proxy.
Self-invocation dan method `final` tidak terintersepsi.

#### K.6.1. Menggunakan advice pada service turunan `BaseService`

Jika sebuah service extends `BaseService` dan lifecycle `execute()` ingin diberi
Aspect Advice, service tersebut wajib override `execute()`, memasang anotasi
advice pada method override, lalu mendelegasikan proses ke `super.execute()`:

```java
@Override
@BeforeExecution
public List<GetNotificationResponse> execute(EmptyRequest request) {
    return super.execute(request);
}
```

Method override tersebut menjadi entry point yang dilihat oleh proxy Spring,
sedangkan `super.execute(request)` tetap menjalankan lifecycle `BaseService`:
pemeriksaan servlet context, logging, `validateRequest()`, dan `buildProcess()`.
Pastikan caller memanggil `execute()` melalui bean service yang di-inject oleh
Spring.

Jangan hanya memasang anotasi advice pada `validateRequest()` atau
`buildProcess()`. Kedua method itu dipanggil secara internal oleh
`BaseService.execute()` pada instance yang sama sehingga terjadi self-invocation
dan proxy Spring tidak mengintersepsinya. Pola override yang sama berlaku untuk
`@AroundExecution`, `@AfterExecution`, `@AfterReturningExecution`, dan
`@AfterThrowingExecution`.

| Masalah | Tindakan perbaikan |
|---|---|
| Property behavior kosong | Isi property behavior yang menjadi pasangan flag aktif. |
| Bean tidak ditemukan | Pastikan package behavior masuk component scan dan nama YAML sama dengan nama bean. |
| Bean memiliki tipe yang salah | Pastikan bean extends base behavior yang sesuai dengan advice. |
| Behavior tidak terpanggil | Pastikan target merupakan Spring bean, method memakai anotasi yang sesuai, dipanggil melalui proxy, dan tidak final. Untuk turunan `BaseService`, override dan anotasi `execute()` seperti contoh di atas. |

Konfigurasi singkat seluruh feature flag tetap tersedia pada
[Panduan Konfigurasi](%281.0.0%29%20CONFIGURATION_GUIDE.md#m-aspect-advice).

## Ringkasan pemilihan utility

| Kebutuhan | API utama | Konfigurasi |
|---|---|---|
| Validasi request programmatic | `ValidationUtility`, `ValidationConfig` | `validation-handler: true` untuk handler library |
| Constraint field | `@FieldPresence`, `@FieldFormat`, `@FieldLength`, `@FieldNumberRange` | Mengikuti bean Jakarta Validator |
| Rate limiter, circuit breaker, retry | `ResilienceService` | `utilities: true` dan `required: true` per fitur |
| Transaksi dengan fallback | `TransactionalExecutor` | `utilities: true` dan transaction manager |
| Lifecycle method berbasis AOP | `@AroundExecution`, `@BeforeExecution`, `@AfterExecution`, `@AfterReturningExecution`, `@AfterThrowingExecution` | Aktifkan flag advice dan isi nama bean behavior pasangannya |
| Tanggal dan waktu | `DateUtility` | Tidak memerlukan bean |
| Operasi file | `FileUtility` | Tidak memerlukan bean |
| Deteksi tipe dan ekstraksi content | `FileInspector` | Bean otomatis dari `foundation-starter` |
| Sanitasi HTML dan pemeriksaan payload | `FileSanitizer` | Bean otomatis dari `foundation-starter` |
| Pembuatan report JasperReports | `ReportBuilder` | Provider runtime dari `foundation-starter` |
| Error operasi I/O terstruktur | `IOFaultException`, `IOFaultMetadata` | Ditangani handler bawaan sebagai file error HTTP 400 |
| Mapping entity dan DTO | `BaseMapper`, `CommonMapperConfig` | MapStruct annotation processor |
| Representasi diagnostic DTO | `MapperUtility` | Tidak memerlukan bean |

Untuk unit test service, mock kontrak `ValidationUtility`, `ResilienceService`,
atau `TransactionalExecutor`. Untuk menguji anotasi DTO, gunakan Jakarta
`Validator` atau `ValidationUtility` yang dibangun melalui `ValidationConfig`.
