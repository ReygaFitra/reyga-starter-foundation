# Panduan Implementasi Controller — 1.0.0

Panduan ini menyediakan contoh implementasi controller menggunakan base class
`BaseController` dan `ResilienceBaseController`.

Untuk contoh end-to-end mulai dari request DTO, implementasi service, penggunaan
servlet parameter, hingga pemanggilan `execute()` di controller, lihat
[Panduan Implementasi Service](%281.0.0%29%20SERVICE_IMPLEMENTATION_GUIDE.md).

Ketika service aplikasi extends `BaseService`, controller harus memanggil
`service.execute(request)` sebagai entry point business flow. Jika service
mengembalikan `true` dari `useHttpServletParameter()`, panggil
`setHttpServletParameter(request, servletRequest, servletResponse)` tepat sebelum
`execute()`.

## 1. Menggunakan `BaseController`

`BaseController` merupakan pilihan standar untuk membuat REST controller. Class
ini menyediakan helper untuk membentuk JSON response secara konsisten.

### Fitur utama

- `createResponse(T data, HttpStatus status)` membuat `ResponseEntity` sederhana
  dengan data dan HTTP status yang diberikan.
- `createResponse(T data, HttpStatus status, String code, String message)` membuat
  `ResponseEntity<ResponseData<T>>` yang berisi status, code, message, dan data.
  Gunakan bentuk ini jika aplikasi menerapkan standard response envelope.

### Langkah 1: siapkan service dan DTO

Gunakan `FindCustomerService`, `FindCustomerRequest`, dan `FindCustomerResponse`
dari [Panduan Service](%281.0.0%29%20SERVICE_IMPLEMENTATION_GUIDE.md).
Service tersebut tidak memerlukan servlet context.

### Langkah 2: buat controller dan panggil execute

```java
package com.example.customer.controller;

import com.example.customer.service.find.FindCustomerRequest;
import com.example.customer.service.find.FindCustomerResponse;
import com.example.customer.service.find.FindCustomerService;
import lombok.RequiredArgsConstructor;
import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;
import reyga.starter.foundation.common.model.dto.response.ResponseData;
import reyga.starter.foundation.core.controller.BaseController;

@RestController
@RequestMapping("/api/customers")
@RequiredArgsConstructor
public class CustomerController extends BaseController {

    private final FindCustomerService findCustomerService;

    @GetMapping("/{id}")
    public ResponseEntity<ResponseData<FindCustomerResponse>> find(@PathVariable String id) {
        FindCustomerRequest request = FindCustomerRequest.builder().customerId(id).build();
        FindCustomerResponse result = findCustomerService.execute(request);
        return createResponse(result, HttpStatus.OK, "00", "Customer berhasil ditemukan");
    }
}
```

Untuk body JSON, terima `@Valid @RequestBody FindCustomerRequest request`,
lalu panggil `findCustomerService.execute(request)`. Untuk query parameter,
gunakan `@RequestParam` dan bentuk DTO seperti contoh path parameter di atas.

### Langkah 3: pasang servlet context jika diperlukan

Pada endpoint yang memanggil service dengan `useHttpServletParameter() == true`,
terima `HttpServletRequest` dan `HttpServletResponse` dari parameter method
controller. Pasang keduanya sebelum eksekusi:

```java
setHttpServletParameter(request, servletRequest, servletResponse);
var result = updateCustomerService.execute(request);
return createResponse(result, HttpStatus.OK, "00", "Customer berhasil diperbarui");
```

Gunakan tipe servlet dari package `jakarta.servlet.http`. Contoh DTO dan endpoint
lengkap tersedia pada bagian service dengan servlet di panduan service.

## 2. Menggunakan `ResilienceBaseController`

`ResilienceBaseController` extends `BaseController` dan menambahkan kemampuan
Resilience4j, seperti Rate Limiter dan Circuit Breaker, pada proses pembentukan
response.

> Perilaku helper: seluruh overload menerima `data`, bukan
> `Supplier<T>`. Artinya, business service sudah selesai dipanggil sebelum helper
> resilience dijalankan. Helper dapat menentukan response success/fallback, tetapi
> tidak mencegah repository, HTTP client, atau business process sebelumnya untuk
> dieksekusi. Gunakan `ResilienceService` di service layer jika proses downstream
> itu sendiri harus dilindungi.

### Prasyarat

Untuk menggunakan `ResilienceBaseController` dengan default bean dari library,
aktifkan konfigurasi berikut:

```yaml
reyga:
  config:
    default-bean:
      utilities: true
    rate-limiter:
      required: true
      timeout-milis: 500
      max-request: 10
      refresh-period-seconds: 60
    circuit-breaker:
      required: true
      failure-rate-threshold: 50
      slow-call-rate-threshold: 50
      slow-call-duration-threshold-seconds: 2
      minimum-number-of-calls: 10
      sliding-window-size: 20
      permitted-number-of-calls-in-half-open-state: 5
      wait-duration-in-open-state-seconds: 30
      automatic-transition-from-open-to-half-open-enabled: true
```

Konfigurasi tersebut membuat bean berikut pada Spring application context:

- `ResilienceService`;
- `RateLimiterConfig`;
- `RateLimiterRegistry`;
- `CircuitBreakerRegistry`.

`RateLimiterConfig` dibentuk dari seluruh property `rate-limiter`, sedangkan
`RateLimiterRegistry` memakai config tersebut sebagai default config. Nilai pada
contoh berarti setiap limiter memperoleh 10 permission per 60 detik dan dapat
menunggu permission maksimal 500 milidetik.

Walaupun controller pada contoh hanya menggunakan rate limiter,
`circuit-breaker.required` tetap diaktifkan karena constructor
`ResilienceBaseController` saat ini selalu membutuhkan `CircuitBreakerRegistry`.
Siapkan juga transaction manager aplikasi untuk menggunakan `utilities: true`.

Detail dan batas nilai setiap property dijelaskan dalam
[Panduan Konfigurasi Foundation](%281.0.0%29%20CONFIGURATION_GUIDE.md).

### Fitur utama

- `createResponseWithRateLimiter(...)` membentuk response melalui Rate Limiter.
  Jika permission tidak tersedia, method mengembalikan HTTP
  `429 Too Many Requests`; data yang menjadi argumen method sudah diproses.
- `createResponseWithCircuitBreaker(...)` membentuk response melalui Circuit
  Breaker. Ketika circuit terbuka, method membentuk fallback HTTP `500`; helper
  ini tidak membungkus pemanggilan business service yang menghasilkan data.

### Contoh Rate Limiter menggunakan config YAML

Inject `RateLimiterConfig` yang tersedia setelah konfigurasi rate limiter diaktifkan. Controller
tidak perlu memanggil `RateLimiterConfig.custom()` atau menduplikasi angka dari
YAML:

```java
package com.example.controller;

import com.example.customer.service.find.FindCustomerRequest;
import com.example.customer.service.find.FindCustomerResponse;
import com.example.customer.service.find.FindCustomerService;
import io.github.resilience4j.circuitbreaker.CircuitBreakerRegistry;
import io.github.resilience4j.ratelimiter.RateLimiterConfig;
import io.github.resilience4j.ratelimiter.RateLimiterRegistry;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;
import reyga.starter.foundation.common.model.dto.response.ResponseData;
import reyga.starter.foundation.core.controller.ResilienceBaseController;
import reyga.starter.foundation.core.service.foundation.ResilienceService;

@RestController
@RequestMapping("/api/rate-limited-customers")
public class RateLimitedCustomerController extends ResilienceBaseController {

    private final FindCustomerService findCustomerService;
    private final RateLimiterConfig rateLimiterConfig;

    public RateLimitedCustomerController(
            ResilienceService resilienceService,
            RateLimiterRegistry rateLimiterRegistry,
            CircuitBreakerRegistry circuitBreakerRegistry,
            RateLimiterConfig rateLimiterConfig,
            FindCustomerService findCustomerService
    ) {
        super(resilienceService, rateLimiterRegistry, circuitBreakerRegistry);
        this.rateLimiterConfig = rateLimiterConfig;
        this.findCustomerService = findCustomerService;
    }

    @GetMapping("/{id}")
    public ResponseEntity<ResponseData<FindCustomerResponse>> getCustomerById(
            @PathVariable String id
    ) {
        // Business service dijalankan sebelum helper rate limiter.
        FindCustomerRequest request = FindCustomerRequest.builder().customerId(id).build();
        FindCustomerResponse result = findCustomerService.execute(request);

        return createResponseWithRateLimiter(result, "00", "Customer berhasil ditemukan", rateLimiterConfig, "customer-get-by-id");
    }
}
```

Gunakan `rlKey` yang stabil dan unik untuk setiap kebijakan, misalnya
`customer-get-by-id`. Pemanggilan dengan key yang sama menggunakan instance limiter
yang sama dari registry. Key yang berbeda membuat instance limiter terpisah,
tetapi semuanya tetap menggunakan `RateLimiterConfig` default yang sama.

Konfigurasi YAML di atas berlaku sebagai konfigurasi rate limiter global. Jika endpoint membutuhkan limit berbeda, aplikasi perlu menyediakan
konfigurasi tambahan secara eksplisit atau menggunakan `ResilienceService` pada
service layer.

## Checklist implementasi controller

- Controller extends `BaseController` atau `ResilienceBaseController` sesuai
  kebutuhan.
- Dependency service menggunakan constructor injection.
- Untuk `BaseService`, controller hanya memanggil `execute(request)` sebagai
  business entry point.
- Servlet-aware service menerima request dan response servlet melalui
  `setHttpServletParameter()` sebelum `execute()`.
- HTTP status, success code, message, dan response envelope dibentuk pada
  controller.
- Business logic, repository access, dan pemetaan domain response tetap berada di
  service.
- Konfigurasi Rate Limiter atau Circuit Breaker menggunakan key yang unik dan
  parameter yang sesuai SLA aplikasi.
