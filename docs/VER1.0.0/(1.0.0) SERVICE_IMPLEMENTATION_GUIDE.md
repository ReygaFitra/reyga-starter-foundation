# Panduan Implementasi Service — 1.0.0

Ikuti panduan ini untuk membuat service dengan `BaseService<Request, Response>`,
memvalidasi input, menjalankan proses bisnis, dan memanggilnya dari controller.

## Sebelum mulai

Siapkan dependency `core`, `common`, dan runtime `foundation-starter` versi
`1.0.0` sesuai [Panduan Konfigurasi](%281.0.0%29%20CONFIGURATION_GUIDE.md).
Aktifkan `reyga.config.default-bean.validation-handler=true` jika menggunakan
`ValidationUtility`. Contoh DTO menggunakan Lombok; aktifkan annotation processing
pada project aplikasi.

Urutan pengerjaan: buat DTO, implementasikan service, lalu hubungkan controller.
Mulai dari kasus tanpa servlet; gunakan kasus servlet hanya jika proses bisnis
memerlukan akses langsung ke request atau response HTTP.

Contoh lengkap menyertakan deklarasi class. Potongan method pada bagian lanjutan
ditambahkan ke class aplikasi yang sesuai; tipe domain seperti `CustomerData`
dan `CustomerRepository` disediakan oleh aplikasi.

## Komponen library yang digunakan

| Komponen | Tanggung jawab |
|---|---|
| `BaseRequest` | Base DTO request dan tempat penyimpanan sementara `HttpServletRequest` serta `HttpServletResponse`. |
| `FoundationService<T, R>` | Kontrak dasar yang mendeklarasikan `R execute(T request)`. |
| `BaseService<T, R>` | Template lifecycle service yang sudah mengimplementasikan `FoundationService<T, R>`. |
| `BaseHttpServletBuilder` | Menyediakan helper untuk memasang atau membaca servlet object pada `BaseRequest`. |
| `BaseController` | Base controller untuk servlet helper dan standard response builder. |
| `ValidationUtility` | Programmatic Jakarta Bean Validation dari dalam service. |

Karena `BaseService` sudah mengimplementasikan `FoundationService`, service
aplikasi tidak perlu menambahkan `implements FoundationService`. Bentuk dasarnya:

```java
@Service
public class FindCustomerService extends BaseService<FindCustomerRequest, FindCustomerResponse> {

    @Override
    protected boolean useHttpServletParameter() {
        return false;
    }

    @Override
    protected void validateRequest(FindCustomerRequest request) {
        // validation
    }

    @Override
    protected FindCustomerResponse buildProcess(FindCustomerRequest request) {
        throw new UnsupportedOperationException("Isi dengan proses bisnis aplikasi");
    }
}
```

## Lifecycle `execute()`

Controller harus memanggil `execute()` sebagai satu-satunya entry point service:

```text
Controller
  -> membuat atau menerima request DTO
  -> memasang servlet context jika service membutuhkannya
  -> service.execute(request)
       -> memeriksa servlet context jika diwajibkan
       -> validateRequest(request)
       -> buildProcess(request)
  -> membentuk HTTP response
```

Jangan memanggil `validateRequest()` atau `buildProcess()` secara langsung dari
controller. Pemanggilan langsung akan melewati sebagian lifecycle `BaseService`.

| Method wajib | Tanggung jawab |
|---|---|
| `useHttpServletParameter()` | Mengembalikan `true` hanya jika business flow membaca servlet request/response. |
| `validateRequest(request)` | Memvalidasi field request dan business precondition sebelum dependency utama dipanggil. |
| `buildProcess(request)` | Membangun dan menjalankan urutan business flow, lalu mengembalikan response. |

`BaseService` digunakan sebagai singleton Spring bean. Jangan menyimpan request,
response, hasil query, atau servlet object pada field service. Gunakan local
variable pada setiap eksekusi.

## Struktur package yang direkomendasikan

```text
customer/
├── controller/
│   └── CustomerController.java
├── repository/
│   └── CustomerRepository.java
└── service/
    ├── find/
    │   ├── FindCustomerRequest.java
    │   ├── FindCustomerResponse.java
    │   └── FindCustomerService.java
    └── update/
        ├── UpdateCustomerRequest.java
        ├── UpdateCustomerResponse.java
        └── UpdateCustomerService.java
```

Gunakan satu class service untuk satu business flow. Nama
`FindCustomerService`, `CreateCustomerService`, dan `UpdateCustomerService` lebih
jelas daripada satu class besar yang menampung seluruh operasi customer.

## Tutorial 1: service tanpa servlet parameter

Gunakan case ini jika business flow hanya membutuhkan data DTO. Service tidak
membaca header, cookie, session, remote address, atau servlet response.

### Request dan response DTO

Seluruh request service wajib extends `BaseRequest`:

```java
package com.example.customer.service.find;

import jakarta.validation.constraints.NotBlank;
import lombok.Getter;
import lombok.NoArgsConstructor;
import lombok.Setter;
import lombok.experimental.SuperBuilder;
import reyga.starter.foundation.common.model.dto.request.BaseRequest;

@Getter
@Setter
@SuperBuilder(toBuilder = true)
@NoArgsConstructor
public class FindCustomerRequest extends BaseRequest {

    @NotBlank
    private String customerId;
}
```

```java
package com.example.customer.service.find;

public record FindCustomerResponse(
        String customerId,
        String name,
        String status
) {
}
```

Hindari memakai entity database langsung sebagai request atau response agar
kontrak business/API tidak terikat pada persistence schema.

### Implementasikan service

```java
package com.example.customer.service.find;

import lombok.RequiredArgsConstructor;
import org.springframework.stereotype.Service;
import reyga.starter.foundation.core.service.base.BaseService;
import reyga.starter.foundation.core.validation.ValidationUtility;

@Service
@RequiredArgsConstructor
public class FindCustomerService extends BaseService<FindCustomerRequest, FindCustomerResponse> {

    private final CustomerRepository customerRepository;

    @Override
    protected boolean useHttpServletParameter() {
        return false;
    }

    @Override
    protected void validateRequest(FindCustomerRequest request) {
        ValidationUtility.chain().validateRequest(request);
    }

    @Override
    protected FindCustomerResponse buildProcess(FindCustomerRequest request) {
        CustomerData customer = customerRepository
                .findById(request.getCustomerId())
                .orElseThrow(() -> new IllegalArgumentException(
                        "Customer not found: " + request.getCustomerId()
                ));

        return new FindCustomerResponse(
                customer.id(),
                customer.name(),
                customer.status()
        );
    }
}
```

`CustomerRepository` dan `CustomerData` merupakan kontrak aplikasi. Gunakan
custom exception yang sesuai standard error aplikasi untuk production code.

### Controller dengan JSON body

```java
package com.example.customer.controller;

import com.example.customer.service.find.FindCustomerRequest;
import com.example.customer.service.find.FindCustomerResponse;
import com.example.customer.service.find.FindCustomerService;
import jakarta.validation.Valid;
import lombok.RequiredArgsConstructor;
import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;
import reyga.starter.foundation.common.model.dto.response.ResponseData;
import reyga.starter.foundation.core.controller.BaseController;

@RestController
@RequestMapping("/api/customers")
@RequiredArgsConstructor
public class CustomerController extends BaseController {

    private final FindCustomerService findCustomerService;

    @PostMapping("/find")
    public ResponseEntity<ResponseData<FindCustomerResponse>> find(@Valid @RequestBody FindCustomerRequest request) {
        return createResponse(findCustomerService.execute(request), HttpStatus.OK, "200000", "Customer retrieved successfully");
    }
}
```

### Controller dengan path atau query parameter

Controller membentuk DTO service, lalu memanggil `execute()`:

```java
@GetMapping("/{customerId}")
public ResponseEntity<ResponseData<FindCustomerResponse>> findById(@PathVariable String customerId) {
    FindCustomerRequest request = FindCustomerRequest.builder()
            .customerId(customerId)
            .build();

    return createResponse(findCustomerService.execute(request), HttpStatus.OK, "200000", "Customer retrieved successfully");
}
```

```java
@GetMapping
public ResponseEntity<ResponseData<FindCustomerResponse>> findByQuery(@RequestParam String customerId) {
    FindCustomerRequest request = FindCustomerRequest.builder()
            .customerId(customerId)
            .build();

    return createResponse(findCustomerService.execute(request), HttpStatus.OK, "200000", "Customer retrieved successfully");
}
```

Penggunaan `@RequestBody`, `@PathVariable`, atau `@RequestParam` tidak berarti
service membutuhkan servlet parameter. Nilainya tetap `false` selama service
tidak membaca `HttpServletRequest` atau `HttpServletResponse`.

## Tutorial 2: service dengan servlet parameter

Gunakan case ini hanya jika business flow benar-benar membutuhkan HTTP context,
misalnya membaca header, cookie, session, request attribute, informasi client,
atau menambahkan response header.

Ketika `useHttpServletParameter()` mengembalikan `true`, `BaseService` mewajibkan
**dua object sekaligus**:

- `HttpServletRequest` pada `BaseRequest.servletRequest`;
- `HttpServletResponse` pada `BaseRequest.servletResponse`.

Walaupun service hanya membaca salah satunya, controller tetap harus memasang
keduanya. Jika salah satu `null`, `execute()` melempar `AppFaultException` dengan
kode `SERVLET_CONTEXT_NOT_FOUND` dan HTTP `500` sebelum logging, validation, dan
proses bisnis dijalankan.

### Request dan response DTO

```java
@Getter
@Setter
@SuperBuilder(toBuilder = true)
@NoArgsConstructor
public class UpdateCustomerRequest extends BaseRequest {

    @NotBlank
    private String customerId;

    @NotBlank
    private String name;
}
```

```java
public record UpdateCustomerResponse(
        String customerId,
        String name,
        String updatedBy
) {
}
```

Field servlet sudah diwarisi dari `BaseRequest` dan bertipe `transient`. Jangan
mendeklarasikan ulang servlet object pada DTO turunan.

### Implementasikan service

```java
@Service
@RequiredArgsConstructor
public class UpdateCustomerService extends BaseService<UpdateCustomerRequest, UpdateCustomerResponse> {

    private final CustomerRepository customerRepository;

    @Override
    protected boolean useHttpServletParameter() {
        return true;
    }

    @Override
    protected void validateRequest(UpdateCustomerRequest request) {
        ValidationUtility.chain().validateRequest(request);

        String actor = request.getServletRequest().getHeader("X-User-Id");
        if (actor == null || actor.isBlank()) {
            throw new IllegalArgumentException("X-User-Id header is required");
        }
    }

    @Override
    protected UpdateCustomerResponse buildProcess(UpdateCustomerRequest request) {
        String actor = request.getServletRequest().getHeader("X-User-Id");

        CustomerData customer = customerRepository.updateName(
                request.getCustomerId(),
                request.getName(),
                actor
        );

        request.getServletResponse().setHeader("X-Updated-By", actor);

        return new UpdateCustomerResponse(
                customer.id(),
                customer.name(),
                actor
        );
    }
}
```

Contoh `X-User-Id` hanya menunjukkan cara membaca header. Untuk identitas pengguna,
gunakan principal terautentikasi atau header yang sudah diverifikasi oleh sistem
autentikasi; jangan mempercayai header bebas dari client.

Jangan menyimpan actor atau servlet object pada field service. Jika metadata HTTP
perlu diolah, gunakan local variable atau private helper stateless.

### Controller menggunakan `BaseController`

`BaseController` mewarisi `setHttpServletParameter()` dari
`BaseHttpServletBuilder`. Panggil helper ini sebelum `execute()`:

```java
@RestController
@RequestMapping("/api/customers")
@RequiredArgsConstructor
public class CustomerCommandController extends BaseController {

    private final UpdateCustomerService updateCustomerService;

    @PutMapping("/{customerId}")
    public ResponseEntity<ResponseData<UpdateCustomerResponse>> update(
            @PathVariable String customerId,
            @Valid @RequestBody UpdateCustomerHttpRequest body,
            HttpServletRequest servletRequest,
            HttpServletResponse servletResponse
    ) {
        UpdateCustomerRequest request = UpdateCustomerRequest.builder()
                .customerId(customerId)
                .name(body.name())
                .build();

        setHttpServletParameter(request, servletRequest, servletResponse);

        return createResponse(updateCustomerService.execute(request), HttpStatus.OK, "200000", "Customer updated successfully");
    }

    public record UpdateCustomerHttpRequest(@NotBlank String name) {
    }
}
```

Urutan yang benar:

```text
build request DTO
  -> setHttpServletParameter(request, servletRequest, servletResponse)
  -> updateCustomerService.execute(request)
  -> createResponse(...)
```

### Controller tanpa `BaseController`

Servlet context dapat dipasang menggunakan setter `BaseRequest`:

```java
request.setServletRequest(servletRequest);
request.setServletResponse(servletResponse);

UpdateCustomerResponse result = updateCustomerService.execute(request);
return ResponseEntity.ok(result);
```

Pastikan kedua setter selalu dipanggil.

### Multipart request

`MultipartFile` bukan servlet parameter yang dimaksud oleh
`useHttpServletParameter()`. Jika service hanya membutuhkan file dan metadata DTO,
service tetap mengembalikan `false`:

```java
@PostMapping(path = "/documents", consumes = MediaType.MULTIPART_FORM_DATA_VALUE)
public ResponseEntity<ResponseData<UploadDocumentResponse>> upload(@RequestPart MultipartFile file, @RequestParam String customerId)
{
    UploadDocumentRequest request = UploadDocumentRequest.builder()
            .customerId(customerId)
            .file(file)
            .build();

    UploadDocumentResponse result = uploadDocumentService.execute(request);

    return createResponse(result, HttpStatus.CREATED, "201000", "Document uploaded successfully");
}
```

Ubah menjadi `true` dan pasang kedua servlet object hanya jika service juga perlu
membaca HTTP context selain file tersebut.

## Memanggil service dari scheduler atau listener

Scheduler, message listener, batch, dan command-line runner tidak memiliki servlet
context. Service tersebut harus menggunakan `useHttpServletParameter() == false`:

```java
@Component
@RequiredArgsConstructor
public class CustomerSynchronizationJob {

    private final SynchronizeCustomerService synchronizeCustomerService;

    @Scheduled(cron = "${customer.sync.cron}")
    public void synchronize() {
        SynchronizeCustomerRequest request = SynchronizeCustomerRequest.builder()
                .source("SCHEDULER")
                .build();

        synchronizeCustomerService.execute(request);
    }
}
```

Jika business flow dipakai dari HTTP dan non-HTTP, jangan membuat mock servlet
object untuk caller non-HTTP. Pisahkan HTTP adapter dari domain service yang
menerima data biasa.

## Membuat service tanpa input bisnis

`execute()` tetap membutuhkan instance request yang extends `BaseRequest`. Jangan
mengirim `null`; buat request kosong yang eksplisit:

```java
@SuperBuilder(toBuilder = true)
@NoArgsConstructor
public class GetSystemStatusRequest extends BaseRequest {
}
```

```java
@GetMapping("/status")
public ResponseEntity<ResponseData<SystemStatusResponse>> status() {
    SystemStatusResponse result = getSystemStatusService.execute(new GetSystemStatusRequest());

    return createResponse(result, HttpStatus.OK, "200000", "System status retrieved successfully");
}
```

Jika service kosong tersebut servlet-aware, pasang kedua servlet object sebelum
memanggil `execute()`.

## Ringkasan case controller

| Input/caller | `useHttpServletParameter()` | Sebelum `execute()` |
|---|---:|---|
| JSON body tanpa akses servlet | `false` | Langsung panggil `execute(request)`. |
| Path/query parameter tanpa akses servlet | `false` | Bentuk DTO, lalu panggil `execute(request)`. |
| Multipart tanpa akses servlet tambahan | `false` | Bentuk DTO berisi file, lalu panggil `execute(request)`. |
| Membaca header/cookie/session/request attribute | `true` | Pasang request dan response servlet. |
| Menulis servlet response/header | `true` | Pasang request dan response servlet. |
| Scheduler/listener/batch | `false` | Bentuk DTO tanpa servlet lalu panggil `execute(request)`. |

## Standard response controller

`BaseController` menyediakan dua bentuk response:

```java
// Body langsung
return createResponse(result, HttpStatus.OK);

// Standard ResponseData<T> envelope
return createResponse(result, HttpStatus.OK,"200000","Operation completed successfully");
```

Business service mengembalikan response DTO. HTTP status, success code, dan
success message tetap menjadi tanggung jawab controller. Exception business yang
telah distandardisasi dapat diteruskan ke exception handler foundation/aplikasi.

## Mengaktifkan validasi

Service yang menggunakan `ValidationUtility` memerlukan konfigurasi:

```yaml
reyga:
  config:
    default-bean:
      validation-handler: true
```

Tanpa konfigurasi tersebut, `ValidationUtility.chain()` melempar
`IllegalStateException`. Validasi Spring MVC melalui `@Valid` berjalan secara
independen. Gunakan `validateRequest()` jika service juga dapat dipanggil dari
non-HTTP channel agar caller tidak melewati validation.

Konfigurasi selengkapnya tersedia pada
[Foundation Configuration Guide](%281.0.0%29%20CONFIGURATION_GUIDE.md).

## Injeksi dependency dan transaksi

Gunakan constructor injection. Jangan membuat concrete service `final` jika
aplikasi memerlukan class-based Spring proxy untuk transaction atau aspect. Hindari
self-invocation pada method yang mengandalkan Spring AOP karena pemanggilan melalui
`this` tidak melewati proxy.

## Menguji service aplikasi

Ikuti naming `should_ExpectedOutput_When_InputCondition` dan gunakan section
`given`, `when`, dan `then`.

### Service tanpa servlet parameter

- `should_ReturnResponse_When_RequestIsValid`
- `should_ThrowException_When_RequestIsInvalid`
- `should_ThrowException_When_DataIsNotFound`
- `should_ExecuteWithoutServletContext_When_ServletParameterIsNotRequired`

### Service dengan servlet parameter

- `should_ReturnResponse_When_RequestAndServletContextAreValid`
- `should_ThrowAppFaultException_When_ServletRequestIsNull`
- `should_ThrowAppFaultException_When_ServletResponseIsNull`
- `should_ThrowException_When_RequiredHeaderIsMissing`

Pada bagian `then`, validasi seluruh response/exception dan dependency interaction:

```java
@Test
void should_ReturnResponse_When_RequestAndServletContextAreValid() {
    // given
    UpdateCustomerRequest request = validRequest();
    request.setServletRequest(servletRequest);
    request.setServletResponse(servletResponse);
    when(servletRequest.getHeader("X-User-Id")).thenReturn("user-01");
    when(customerRepository.updateName("CUS-01", "Reyga", "user-01"))
            .thenReturn(updatedCustomer());

    // when
    UpdateCustomerResponse result = service.execute(request);

    // then
    assertThat(result.customerId()).isEqualTo("CUS-01");
    assertThat(result.name()).isEqualTo("Reyga");
    assertThat(result.updatedBy()).isEqualTo("user-01");
    verify(servletRequest, times(2)).getHeader("X-User-Id");
    verify(servletResponse).setHeader("X-Updated-By", "user-01");
    verify(customerRepository).updateName("CUS-01", "Reyga", "user-01");
    verifyNoMoreInteractions(customerRepository, servletRequest, servletResponse);
}
```

Untuk missing servlet context, pastikan dependency business tidak dipanggil:

```java
verifyNoInteractions(customerRepository);
```

## Checklist implementasi

- Request extends `BaseRequest`.
- Concrete service extends langsung ke `BaseService<Request, Response>`.
- Service diberi `@Service` dan menggunakan constructor injection.
- Ketiga lifecycle method diimplementasikan.
- `useHttpServletParameter()` hanya `true` untuk dependency terhadap HTTP context.
- Controller memasang **request dan response servlet** sebelum `execute()` untuk
  service servlet-aware.
- Controller hanya memanggil `execute()`, bukan lifecycle method internal.
- HTTP status dan response envelope dibentuk pada controller.
- Service tidak menyimpan per-request state atau servlet object pada field.
- `validation-handler` aktif jika memakai `ValidationUtility`.
- Positive dan negative test memvalidasi result serta dependency interaction.

## Troubleshooting

| Gejala | Penyebab dan tindakan |
|---|---|
| `Servlet Context Not Found` | Service mengembalikan `true`, tetapi salah satu servlet object belum dipasang. Panggil `setHttpServletParameter()` sebelum `execute()`. |
| `ValidationUtility bean is not available` | Aktifkan `reyga.config.default-bean.validation-handler=true` atau gunakan validator aplikasi. |
| Bean service tidak ditemukan | Pastikan service diberi `@Service` dan berada dalam component scan. |
| Servlet data tertukar antar-request | Jangan menyimpan servlet object atau request DTO pada field singleton service. |
| Business flow melewati lifecycle | Pastikan caller memanggil `execute()`, bukan method internal service. |
| Non-HTTP caller selalu gagal | Pastikan service non-HTTP mengembalikan `false` dari `useHttpServletParameter()`. |

Panduan controller lainnya tersedia pada
[Panduan Implementasi Controller](%281.0.0%29%20CONTROLLER_IMPLEMENTATION_GUIDE.md).
